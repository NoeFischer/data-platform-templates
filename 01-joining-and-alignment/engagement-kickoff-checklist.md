# Engagement Kickoff Checklist

> Your personal checklist for the first 1-2 weeks of a new engagement. Written for the common case: you're joining a project that's already in motion, you may not be the lead, and nobody's going to hand you context — you have to go get it.

## Before day 1

- [ ] Contract / SOW reviewed — understand what you're actually accountable for
- [ ] Key contacts identified (sponsor, day-to-day lead, technical counterpart)
- [ ] Access requests submitted (email, Slack/Teams, repos, cloud accounts, VPN)
- [ ] Read whatever documentation they've shared (even if it's outdated — that tells you something)
- [ ] Prep your "first meeting" questions (see meeting prep template)
- [ ] Set up your personal project folder (copy this repo)

## Week 1: Listen and learn

### Understand the people

- [ ] Meet the sponsor — ask: "What does success look like to you personally?"
- [ ] Meet the project lead — ask: "What's been tried before? What went wrong?"
- [ ] Meet the technical team — ask: "What are you most worried about?"
- [ ] Identify who actually influences decisions (this is rarely the org chart)
- [ ] Ask: "Who will resist this project and why?"
- [ ] Start your stakeholder map — even if just for yourself

### Understand the current state

- [ ] Get a walkthrough of what exists today (sources, tools, flows, infrastructure)
- [ ] Ask to see the dashboards and reports people actually use
- [ ] Ask: "What question can you not answer today that you wish you could?"
- [ ] Review whatever passes for documentation (architecture diagrams, runbooks, wikis)
- [ ] Look at the code / pipelines / configs — what's the actual quality?
- [ ] Find out what the procurement / security review process looks like

### Understand the project

- [ ] Is there a project charter (or equivalent)? Read it. If not, note what's missing.
- [ ] Is there a RACI? If not, observe: who decides what? Where do decisions stall?
- [ ] Are there ADRs? If not, ask "why did we pick X?" and write down the answers for yourself
- [ ] What's the current plan and timeline? Is anyone tracking progress?
- [ ] What scope changes have happened? How were they handled?
- [ ] What has the team shipped so far? What's been harder than expected?

### Set yourself up

- [ ] Agree on communication norms (where to chat, where to email, what warrants a meeting)
- [ ] Understand the team's ceremonies (standups, reviews, retros) — join them, don't add new ones yet
- [ ] Start your personal decision log — write down every decision you witness
- [ ] Clarify your working hours and availability expectations

## Week 2: Synthesize and act

- [ ] Write your situation assessment (see template) — share it with the sponsor and lead
- [ ] Identify one quick win — something you can deliver in 2-4 weeks that builds credibility
- [ ] Complete the stakeholder map
- [ ] Run the priorities alignment canvas if stakeholders seem misaligned (or keep the results private if the politics aren't right)
- [ ] Start the complexity check on any technical decisions that feel over-engineered

## If you're also the lead

_Additional items if you're running the project, not just contributing to it._

- [ ] Draft or review the project charter
- [ ] Set up the RACI and review it with stakeholders
- [ ] Establish governance ceremonies (steering, status reporting)
- [ ] Set up the decision log as a shared artifact
- [ ] Agree on scope change process with the sponsor

## Personal reminders

- [ ] Don't start solutioning in week 1. You don't understand the problem yet.
- [ ] Don't promise timelines until you understand the environment.
- [ ] Take notes in every meeting. You'll forget who said what by week 3.
- [ ] Find the person who's been there longest. Buy them coffee. They know everything.
- [ ] Your first impression matters. Use it to set expectations about rigor, not to be agreeable.
- [ ] The things that make you uncomfortable in week 1 are usually the things the team has normalized. Pay attention to that discomfort — it's data.
